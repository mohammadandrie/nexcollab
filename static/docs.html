Nexcollab — Workspace tim dengan AI yang ngerti siapa lagi ngomong

Dokumentasi konsep, cara kerja, dan alur tim. Disusun buat tim Nexcollab — Tyo, Hamfik, Hari, Chalif, Andre — biar pas mulai bangun, semua orang udah satu peta.

TL;DR untuk yang males baca panjang

Nexcollab itu workspace kerja tim — isinya kita berlima + Hermes, AI agent yang udah Andre pakai sehari-hari. Tiap orang punya chat pribadi buat brainstorm sendirian sama Hermes (boleh ngawur, gak ada yang nge-judge). Kalau hasilnya udah matang, klik tombol 📤 Send to Chat All — pesannya pindah ke Chat All, channel resmi project yang semua tim baca. Hermes satu otak, tapi tau siapa yang lagi ngomong dan jobdesc-nya apa. Tyo tanya soal user story, Hari tanya soal implementasi-nya — Hermes nyambung di kedua sisi tanpa kamu perlu jelasin ulang.

1Apa itu Nexcollab?

Nexcollab adalah workspace kerja tim berbasis chat, di mana semua anggota tim ngerjain project bareng satu AI agent (Hermes) sebagai rekan kerja virtual.

Bayangin punya 1 rekan kerja super jago yang:

  • Selalu standby 24/7
  • Tau context project lengkap dari awal sampai sekarang
  • Bisa coding, design review, bikin dokumen, debug bug, eksekusi terminal, push ke git
  • Sopan ngerti siapa yang lagi ngomong dan jobdesc-nya apa

Bedanya sama ChatGPT / Claude.ai / LibreChat

Mereka
Chat sama AI model polos — cuma bisa jawab. Mau bikin file? Push code? Cek server? Jalanin test? Semuanya manual, di luar chat.
Nexcollab
Chat sama Hermes Agent — bisa eksekusi terminal, edit file, push git, kirim Telegram, baca Figma, generate mockup, deploy. Kerja beneran, bukan cuma jawab.

Singkatnya: ChatGPT itu asisten omongan, Hermes di Nexcollab itu asisten yang punya tangan.

31 otak, 5 topi

Ini konsep paling penting di Nexcollab — gampang miss, tapi inilah yang bikin beda dari "5 orang yang punya akun ChatGPT masing-masing".

Hermes itu satu AI. Memori, history project, file, decision log — semuanya share. Tapi pas ngobrol sama Tyo (PM), gaya jawabnya beda dari pas ngobrol sama Hari (Dev). Hermes tau yang lagi ngomong siapa, dan otomatis ganti "topi" jawabannya.

Contoh konkret — kalau Tyo nanya "gimana fitur export PDF?", Hermes jawab dari sudut PM: scope, acceptance criteria, prioritas. Kalau Hari nanya hal yang sama, Hermes jawab dari sudut Dev: library mana, schema database, estimate jam.

Yang ngobrolHermes fokus ke

UX · Hamfik Wireframe, design tokens, accessibility, visual hierarchy, Figma
DEV · Hari & Chalif Implementasi, code review, branch, deploy, performance
QA · Andre Test plan, edge case, bug investigation, regression risk

Kenapa "1 otak" bukan "5 AI terpisah"?

Coba bayangin skenario realistis:

  1. Senin — Tyo ngobrol sama Hermes 1 jam, finalisasi user story fitur export PDF.
  2. Selasa — Hari mau implement. Buka chat pribadinya, bilang "gw mau implement export PDF, cek user story Tyo".
  3. Hermes udah tau — Senin udah ikut diskusi sama Tyo. Langsung kasih plan implementasi yang nyambung sama keputusan Senin. Gak perlu Hari paste-paste user story dari mana-mana.

Itu yang gak kelar di ChatGPT 5 akun: tiap orang punya context terisolasi, tiap hand-off harus copy-paste manual dan rentan info hilang.

5Chat Pribadi vs Chat All

Dua jenis ruang chat. Beda peran, beda aturan.

💬 Chat Pribadi private
Ruang draft / brainstorm. Cuma yang punya yang lihat.
✓ Bebas ngobrol, nyoba, eksplor
✓ Boleh ngawur, bingung, mind-change
✓ Gak ada yang nge-judge
✓ Gaya: "DM sebelum bawa ke meeting"
📢 Chat All shared
Decision log project. Semua tim baca.
✓ Cuma isi yang udah matang
✓ Tagged: siapa kirim, dari role apa
✓ Threading per topic
✓ Gaya: "channel #project di Slack — tapi rapih"

Aturan main

  • Pesan masuk ke Chat All cuma lewat tombol 📤 Send to Chat All dari chat pribadi — gak bisa ngetik langsung di Chat All. Ini biar feed-nya tetap bersih.
  • Chat pribadi privacy total — bahkan founder gak baca tanpa diundang.
  • Chat All append-only — bisa edit caption sendiri (kayak Slack edit), tapi gak bisa hapus thread orang lain.

6Mekanisme "Send to Chat All"

Ini jembatan antara chat pribadi dan Chat All. Tombol promote yang muncul di response Hermes pas ada yang layak di-share.

Step-by-step

  1. Di chat pribadi, Hermes kasih response yang udah matang (user story, mockup, plan, test scenario, dll).
  2. Di bawah response itu muncul tombol 📤 Send to Chat All.
  3. Klik → modal preview muncul.
  4. Isi caption singkat (1–2 kalimat konteks).
  5. Pilih tag role yang relevan — @pm @ux @dev @qa. Tag = notif ke role itu.
  6. Pilih thread: bikin baru, atau reply ke thread Chat All yang udah ada.
  7. Klik Send. Pesan muncul di Chat All sebagai kartu lengkap dengan author, role, caption, dan artifact-nya.
▶ Kenapa harus pakai modal, gak langsung kirim aja?
Biar feed Chat All bersih. Modal maksa kamu mikir 5 detik: "caption-nya apa, role mana yang harus tau?" — itu bedanya antara channel yang nyaman dibaca minggu depan vs channel yang berisik dan jadi noise.

9"Tapi AI di VS Code juga bisa coding, kan?"

Pertanyaan wajar — Cursor, Copilot, Continue, Cody, Windsurf, Codeium, Trae, Kiro, semua bisa nulis & edit code di editor. Jadi kenapa Nexcollab?

Jawaban singkat: AI di VS Code = pair programmer untuk 1 dev. Hermes di Nexcollab = anggota tim multi-role yang shared context.

Bedanya gak di "siapa lebih jago coding" — keduanya jago. Bedanya di scope kerjanya:

AspekAI di VS Code (Cursor / Copilot / dll.)Hermes di Nexcollab
Fokus utama Bantu dev nulis code di file yang sedang dibuka Workflow tim — PM nulis spec, UX bikin mockup, Dev implement, QA test, semua di satu tempat
Siapa yang pakai Cuma Dev (Hari, Chalif). PM/UX/QA gak buka VS Code Semua 5 role tim. PM gak perlu install IDE
Context yang diingat File yang lagi dibuka + chat session (per dev, per project) Cross-role: spec dari Tyo, mockup Hamfik, code Hari, test plan Andre — Hermes tau semuanya, lintas hari, lintas orang
Decision log Tersebar di chat tab masing-masing dev — lost kalau IDE di-restart / project di-clone ulang Chat All = single source of truth, persistent, di-share ke seluruh tim
Hand-off antar role Manual: Dev export hasil chat → paste ke Slack → kirim ke QA Tinggal klik 📤 Send to Chat All — tag @qa, otomatis muncul di feed
Eksekusi di luar IDE Terbatas: edit file, run terminal, sebagian bisa git push Push git, deploy server, kirim Telegram, baca Figma, generate mockup HTML, run cron job, lempar webhook
Privacy chat Per dev — orang lain gak lihat (tapi juga gak ada konsep "share" yang formal) By design: chat pribadi private, Chat All shared eksplisit

Bukan saingan — komplementer

Kalau Hari & Chalif tetap mau pakai Cursor / Copilot di VS Code lokal, silakan. Itu malah ideal:

Di VS Code lokal
Cursor / Copilot bantu Hari nulis code line-by-line, autocomplete, refactor di file yang lagi dibuka. Tactical pair programming.
Di Nexcollab
Hermes lihat keseluruhan project: ngerti context dari Tyo (spec) sampai Andre (test). Bisa auto-implement seluruh feature, push ke branch sendiri, dan kasih tau tim. Strategic teammate.

Dua tool ini gak conflict — bahkan satu workflow bisa pakai keduanya:

  1. Hermes auto-implement fitur Export PDF, push ke branch ai/export-pdf
  2. Hari pull branch itu di laptopnya, buka VS Code
  3. Hari pakai Cursor buat tweak detail kecil yang dia mau ubah (style, edge case)
  4. Hari push commit follow-up, lalu merge ke main

Jadi: Nexcollab gak ngegantiin VS Code — dia ngisi gap yang VS Code memang gak dibikin untuk itu: koordinasi tim multi-role.

10Human-in-the-loop: AI push, tim review, manusia yang merge

Ini bagian penting yang sering bikin tim ragu pakai AI agent: "kalau AI bisa push code sendiri, terus kontrol kita di mana?"

Jawaban Nexcollab: AI cuma boleh push ke branch-nya sendiri, gak boleh merge ke main. Manusia tetap final approver.

Aturan branching

✓
Hermes boleh:
Bikin branch baru dengan prefix ai/ (misal ai/export-pdf, ai/fix-login-bug), commit & push ke branch itu, buka Pull Request / Merge Request, kasih komentar.
✕
Hermes gak boleh:
Push langsung ke main / develop / production. Force-push. Merge PR. Hapus branch orang lain. Ubah git config. Skip CI/CD checks.
⚙
Branch protection (di GitHub/GitLab):
Branch main di-protect — required review minimal 1 orang manusia, required CI green, no direct push. Ini level repo, gak bergantung sama goodwill Hermes.

Flow lengkap: dari request sampai merge

1
Tim minta lewat chat (Tyo · PM)
Di Chat All thread Export PDF, Tyo nulis: "@dev — gas implement, target Jumat."
2
Hermes coding di branch sendiri
Hermes bikin branch ai/export-pdf, tulis semua kode (backend route, weasyprint integration, frontend ExportButton sesuai mockup Hamfik), commit per logical chunk.
$ git checkout -b ai/export-pdf
$ # …generate kode…
$ git add -A && git commit -m "feat: add PDF export route"
$ git commit -m "feat: ExportButton component"
$ git push -u origin ai/export-pdf
3
Hermes buka Pull Request
PR description otomatis: ringkasan perubahan, file yang disentuh, mockup yang dipakai, test scenario yang udah dilewati, link ke thread Chat All. Ditandai ai-generated, request reviewer @hari @chalif.
● PR #42 · feat: Export Chat to PDF ai-generated
From ai/export-pdf → main
📝 12 files changed · +487 / -23
🔗 Linked: Chat All thread "Export PDF"
👥 Reviewers requested: @hari @chalif
4
Dev pull branch ke local & test
Hari clone branch ke laptopnya, jalanin di VS Code, test manual.
$ git fetch && git checkout ai/export-pdf
$ npm install && npm run dev
$ # …klik tombol Export di UI, cek hasil PDF…
$ npm test
✓ 24 tests passed
5
Dev review code & kasih feedback
Di GitHub/GitLab UI, Hari kasih komentar inline: "library weasyprint slow buat chat 500+ pesan, ganti pakai chromium-pdf?". Bisa juga balik ke chat pribadi, tag thread itu, minta Hermes revise. Hermes push commit baru ke branch yang sama.
6
QA verify di staging
CI auto-deploy branch ke staging URL ai-export-pdf.staging.maxndre.com. Andre run test plan dari Chat All — manual + automated. Approve di PR kalau lulus.
7
Manusia yang klik Merge
Setelah dev approve + QA approve + CI green, manusia (biasanya dev senior atau Andre) klik tombol Merge Pull Request di GitHub/GitLab. Hermes secara prinsip gak punya akses ke aksi ini.

Kenapa flow-nya begini

  • Code review tetap manusia — AI bisa kasih kode bagus 95% kasus, tapi 5% kasus aneh (perf regression, security gap, design conflict) butuh mata manusia yang ngerti context bisnis.
  • Branch ai/ jelas asal-usulnya — gampang difilter di git history, kalau ada bug bisa dilacak balik ke chat thread di Chat All yang generate kode itu.
  • CI/CD jadi safety net — test, lint, security scan jalan otomatis. Kalau Hermes nge-break sesuatu, CI red sebelum sempat di-merge.
  • Tetap bisa manual coding — kalau Hari mau nulis code sendiri tanpa Hermes, push ke branch hari/ seperti biasa. Hermes gak campur tangan.

Setting branch protection (sekali setup)

Di GitHub: Settings → Branches → Add rule untuk main:

☑ Require pull request before merging
☑ Require approvals: minimum 1 reviewer
☑ Require status checks to pass (CI)
☑ Require branches to be up to date
☐ Allow force pushes — leave unchecked
☐ Allow deletions — leave unchecked

Token Hermes di-scope ke "Contents: write, Pull requests: write" — gak punya permission Admin. Bahkan kalau Hermes mau bypass branch protection, tokennya gak boleh.

11Akses & privacy

  • Cuma 5 orang tim yang bisa login — Tyo, Hamfik, Hari, Chalif, Andre.
  • Login pakai email + password (bisa nambah Google login nanti).
  • Chat pribadi: cuma yang punya yang lihat. Bahkan Andre (admin) gak bisa intip chat pribadi Tyo. Masuk ke Chat All cuma kalau pemiliknya promote sendiri.
  • Chat All: semua anggota project itu lihat. PM gak bisa exclude QA dari Chat All di project yang sama — kalau gak mau dilihat, jangan masuk Chat All-nya.
  • Project terpisah: project A gak bisa baca chat project B kecuali user-nya invited ke kedua project.
  • Server: self-hosted di VPS Andre — data gak ke pihak ketiga, kecuali API call ke model AI (lewat gateway internal).

14FAQ

▶Apa bedanya sama Slack + ChatGPT?
Slack + ChatGPT itu 2 tool terpisah. Chat sama AI di ChatGPT, hasil keputusannya copy-paste manual ke Slack. Nexcollab gabung keduanya: AI di dalam workspace, dan AI itu bisa eksekusi (push code, generate file). Selain itu, Hermes punya shared memory antar anggota tim — ChatGPT akun terpisah gak bisa.
▶Hermes baca chat pribadi orang lain?
Tidak. Chat pribadi bener-bener private. Yang Hermes "ingat" bareng-bareng cuma:
  • Apa yang di-promote ke Chat All
  • File yang di-attach di project (mockup, code, dokumen)
  • State project (commit, deploy, dll.)
Brainstorm liar Tyo di chat pribadinya gak akan pernah dilihat Hari, dan Hermes gak akan pernah quote dari sana ke chat lain.
▶Kalau Hermes-nya error / down, kerja jadi gak bisa?
Chat tetap jalan — kayak Slack tanpa AI. Yang gak jalan cuma response Hermes. Kita juga punya fallback: kalau gateway utama down, Hermes auto-fallback ke OpenRouter. Plus, semua chat history kesimpan di database — gak hilang kalau Hermes restart.
▶Bisa add anggota tim baru nanti?
Bisa. Admin invite via email, set role-nya (PM/UX/DEV/QA/custom). Anggota baru otomatis bisa baca Chat All semua project yang dia di-invite.
▶Mockup-nya beneran jalan / cuma gambar?
Mockup di nexcollab.maxndre.com itu HTML statis — interaktif (tombol, modal, switch view jalan), tapi belum nyambung ke engine. Tujuannya buat tim bisa kebayang UI-nya sebelum kita commit ke build full app.
▶Kalau klien mau pakai juga buat tim mereka?
Bisa di-extend ke multi-workspace nanti — tiap tim punya workspace isolated. Tapi v1 fokus dulu ke 1 workspace (kalian). Kalau Phase 2 mau jadi produk untuk klien, tinggal bikin workspace switcher di top bar.
